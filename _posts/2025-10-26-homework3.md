## Introduction to RSA Vulnerability Analysis

In this homework, I explore a critical vulnerability that arises when RSA encryption is improperly implemented on a character-by-character basis. While RSA is considered one of the most secure public-key cryptosystems when used correctly, applying it letter-by-letter transforms it into what is essentially a substitution cipher—making it vulnerable to the same statistical attacks that break the Caesar cipher.

This analysis demonstrates why proper cryptographic implementation is crucial: even mathematically strong algorithms can become weak if applied incorrectly.

## Theoretical Background

### RSA Encryption: Brief Overview

**RSA (Rivest-Shamir-Adleman)** is a public-key cryptosystem published in 1977. It relies on the mathematical difficulty of factoring large prime numbers.

**Standard RSA process:**
1. Generate two large prime numbers: p and q
2. Calculate n = p × q (the modulus)
3. Calculate φ(n) = (p-1)(q-1) (Euler's totient function)
4. Choose public exponent e (commonly 17 or 65537)
5. Calculate private exponent d ≡ e⁻¹ (mod φ(n))

**Encryption and Decryption:**
- Encryption: C = M^e mod n
- Decryption: M = C^d mod n

Where M is the plaintext message and C is the ciphertext.

### The Fatal Flaw: Character-by-Character Application

**Proper RSA usage:**
- Encrypts entire blocks of data
- Uses padding schemes (OAEP, PKCS#1)
- Each encryption produces different ciphertext (non-deterministic)
- No pattern preservation

**Improper RSA usage (letter-by-letter):**
- Each character encrypted independently
- Same character always produces same number
- Statistical patterns completely preserved
- Vulnerable to frequency analysis

**Why this is catastrophic:**
```
Plaintext:  E    E    E    T    T    A
            ↓    ↓    ↓    ↓    ↓    ↓
Encrypted: 2603 2603 2603 2744 2744 1915

Every 'E' → always 2603
Every 'T' → always 2744
```

This transforms RSA from a secure public-key cryptosystem into a simple **monoalphabetic substitution cipher**, which has been breakable since the 9th century.

### Why Frequency Analysis Works

Natural languages have non-uniform letter distributions. In English:
- 'E' appears ~12.49% of the time
- 'T' appears ~9.28% of the time
- 'Z' appears ~0.09% of the time

When RSA is applied letter-by-letter, these frequency patterns are preserved perfectly in the ciphertext, allowing us to:
1. Count encrypted number frequencies
2. Map most frequent number → 'E'
3. Map second most frequent → 'T'
4. Continue for all letters

## Methodology

### Dataset Selection and RSA Parameters

For this analysis, I selected the first chapter of **"The Hound of the Baskervilles"** by Sir Arthur Conan Doyle (1902), containing approximately 9,600 characters of English text.

**RSA Parameters Used:**
- Prime p = 61
- Prime q = 53

- Public exponent e = 17
- Private key d = 2,753

**Note:** These are intentionally small primes for educational purposes. In practice, RSA uses 2048-bit or larger primes (over 600 digits). However, the vulnerability we're exploiting exists regardless of key size when RSA is applied character-by-character.

### Multi-Phase Attack Strategy

The attack employs a sophisticated three-phase optimization approach:

#### Phase 1: Initial Frequency Mapping
- Count frequency of each encrypted number
- Sort numbers by frequency (descending)
- Sort expected English letters by frequency (descending)
- Create mapping: most frequent number → 'E', second → 'T', etc.

**Used Distance Metric:**
```
Score = (1/26) × Σ|freq_observed_i - freq_expected_i|
```
Where i is the position in the frequency ranking. This metric measures average deviation between observed and expected frequencies at corresponding positions.

#### Phase 2: Bigram Optimization
Bigrams (two-letter combinations) are more discriminative than single letters. Common English bigrams: TH, HE, IN, ER, AN, RE...

**Hill-climbing algorithm:**
1. Start with Phase 1 mapping
2. Try swapping pairs of frequently-used letters
3. Count occurrences of common English bigrams
4. Keep swaps that increase the bigram score
5. Repeat until no improvement

This phase primarily optimizes the most frequent letters (E, T, A, O, I, N, S, H, R, D).

#### Phase 3: Rare Letter Optimization
After bigram optimization, common letters are usually correct, but rare letters (J, K, Q, X, Z, V, W, B, G, Y, P, F) may still be incorrectly mapped.

**Strategy:**
1. Focus on the 12 least frequent letters
2. Try swapping pairs within this subset
3. Score using trigrams (three-letter combinations: THE, AND, ING, VER, ION, etc.)
4. Trigrams are highly discriminative and help fix residual mapping errors among rare letters

**Why this works:** Bigram scores are dominated by frequent letter pairs (e.g., TH, HE, IN), so rare-letter errors often survive the first optimization.
Trigram scoring, however, captures broader contextual patterns and highlights inconsistencies that bigrams miss.

During trigram optimization, several meaningful corrections emerged — such as U↔M, D↔C, and F↔C — which improved alignment with high-frequency trigrams like VER, ION, and ENT.

For instance, words such as **EVERY** or **EXAMPLE** are sensitive to these mappings: an incorrect swap would break expected trigrams (VER, AMP), sharply lowering the trigram score.
By exploiting these high-information sequences, **the trigram stage refines the mapping of rare letters** that bigram optimization alone cannot reliably recover.

   def gcd(a, b):
      """Calculate Greatest Common Divisor"""
      while b != 0:
         a, b = b, a % b
      return a

   def mod_inverse(e, phi):
      """Calculate modular inverse using Extended Euclidean Algorithm"""
      m0, x0, x1 = phi, 0, 1
      if phi == 1:
         return 0
      while e > 1:
         q = e // phi
         phi, e = e % phi, phi
         x0, x1 = x1 - q * x0, x0
      return x1 + m0 if x1 < 0 else x1

   def mod_pow(base, exp, mod):
      """Fast modular exponentiation"""
      result = 1
      base = base % mod
      while exp > 0:
         if exp % 2 == 1:
               result = (result * base) % mod
         exp = exp >> 1
         base = (base * base) % mod
      return result

   def generate_rsa_keys(p=61, q=53, e=17):
      """
      Generate RSA keys with given primes.
      Using small primes for educational purposes - INSECURE!
      """
      n = p * q
      phi = (p - 1) * (q - 1)
      d = mod_inverse(e, phi)
      return {
         'p': p,
         'q': q,
         'n': n,
         'e': e,
         'd': d,
         'phi': phi
      }

   def rsa_encrypt_char(char, e, n):
      """Encrypt a single character using RSA"""
      m = ord(char)
      return mod_pow(m, e, n)

   def rsa_decrypt_char(cipher_num, d, n):
      """Decrypt a single number using RSA"""
      m = mod_pow(cipher_num, d, n)
      return chr(m)

   def rsa_encrypt_text(text, e, n):
      """
      Encrypt text letter-by-letter using RSA.
      This is INSECURE and vulnerable to frequency analysis!
      """
      encrypted = []
      for char in text:
         if char.isalpha():
               encrypted.append(rsa_encrypt_char(char.upper(), e, n))
         else:

      return encrypted

   def rsa_decrypt_text(encrypted_numbers, d, n):
      """Decrypt RSA encrypted numbers back to text"""
      decrypted = []
      for num in encrypted_numbers:
         if num is not None:
               decrypted.append(rsa_decrypt_char(num, d, n))
         else:
               decrypted.append(' ')
      return ''.join(decrypted)

   def analyze_frequency(text):
      """
      Analyzes letter frequency in text.
      Returns dictionary of letter: percentage and total letter count.
      """
      letters = [c.upper() for c in text if c.isalpha()]
      total = len(letters)
      if total == 0:
         return {}, 0
      counts = Counter(letters)
      frequencies = {letter: (count / total) * 100 
                     for letter, count in counts.items()}
      for letter in string.ascii_uppercase:
         if letter not in frequencies:
               frequencies[letter] = 0.0
      return dict(sorted(frequencies.items())), total

   def analyze_number_frequency(encrypted_numbers):
      """
      Analyzes frequency of encrypted numbers.
      Returns dictionary of number: percentage and total count.
      """
      numbers = [n for n in encrypted_numbers if n is not None]
      total = len(numbers)
      if total == 0:
         return {}, 0
      counts = Counter(numbers)
      frequencies = {num: (count / total) * 100 
                     for num, count in counts.items()}
      return dict(sorted(frequencies.items(), key=lambda x: x[1], reverse=True)), total

   def average_distance_score(observed_freq, expected_freq, sorted_letters):
      """
      Calculate average distance between observed and expected frequencies.
      This is the professor's suggested metric.
      """
      total_distance = 0
      count = 0
      for i, letter in enumerate(sorted_letters):
         if i < len(sorted_letters):
               obs = observed_freq.get(letter, 0)
               exp = expected_freq.get(letter.lower(), 0)
               total_distance += abs(obs - exp)
               count += 1
      return total_distance / count if count > 0 else float('inf')

   def chi_squared_score(observed_freq, expected_freq):
      """
      Calculates chi-squared statistic between observed and expected frequencies.
      Lower score = better match.
      """
      score = 0
      for letter in string.ascii_uppercase:
         expected = expected_freq.get(letter.lower(), 0.1)
         observed = observed_freq.get(letter, 0)
         if expected > 0:
               score += ((observed - expected) ** 2) / expected
      return score

   def count_ngrams(text, n=2):
      """Count occurrences of n-grams in text"""
      ngrams = Counter()
      text_upper = text.upper()
      for i in range(len(text_upper) - n + 1):
         ngram = text_upper[i:i+n]
         if all(c.isalpha() for c in ngram) and len(ngram) == n:
               ngrams[ngram] += 1
      return ngrams

   def score_bigrams(text):
      """Score text based on common English bigrams"""
      bigrams = count_ngrams(text, n=2)
      score = sum(bigrams.get(bg, 0) for bg in COMMON_BIGRAMS)
      return score

   def score_trigrams(text):
      """Score text based on common English trigrams"""
      trigrams = count_ngrams(text, n=3)
      score = sum(trigrams.get(tg, 0) for tg in COMMON_TRIGRAMS)
      return score

   def score_combined(text, bigram_weight=1.0, trigram_weight=2.0):
      """
      Combined scoring using both bigrams and trigrams.
      Trigrams have higher weight as they're more discriminative.
      """
      bi_score = score_bigrams(text)
      tri_score = score_trigrams(text)
      return bigram_weight * bi_score + trigram_weight * tri_score

   def optimize_mapping_with_ngrams(encrypted_numbers, initial_mapping, 
                                    max_iterations=100, top_n=10,
                                    use_trigrams=False, use_annealing=False):
      """
      Optimize mapping using hill-climbing with n-gram scoring.
      HOW IT WORKS:
      1. Start with initial mapping (based on letter frequencies)
      2. Calculate initial score (count of common bigrams/trigrams)
      3. Try swapping pairs of letters in the mapping
      4. If swap improves score, keep it
      5. Repeat until no improvement found
      For trigrams, uses simulated annealing to escape local maxima.
      Args:
         encrypted_numbers: List of encrypted numbers
         initial_mapping: Initial number->letter mapping
         max_iterations: Maximum number of iterations
         top_n: How many of the most frequent numbers to consider for swapping
         use_trigrams: If True, use trigrams; if False, use bigrams
         use_annealing: If True, use simulated annealing (accepts worse solutions sometimes)
      """
      import math
      import random
      best_mapping = initial_mapping.copy()
      current_mapping = initial_mapping.copy()
      if use_trigrams:
         score_func = score_trigrams
         ngram_type = "trigrams"
      else:
         score_func = score_bigrams
         ngram_type = "bigrams"
      best_score = score_func(decrypt_with_mapping(encrypted_numbers, best_mapping))
      current_score = best_score
      attempts = [{
         'iteration': 0,
         'score': best_score,
         'mapping': best_mapping.copy(),
         'preview': decrypt_with_mapping(encrypted_numbers, best_mapping)[:100],
         'type': ngram_type
      }]
      improved = True
      iteration = 0
      temperature = 100.0
      cooling_rate = 0.95
      print(f"   Starting {'simulated annealing' if use_annealing else 'hill-climbing'} with {ngram_type}...")
      print(f"   Initial score: {best_score}")
      print(f"   Search space: top {top_n} letters")
      while improved and iteration < max_iterations:
         improved = False
         iteration += 1
         numbers = list(current_mapping.keys())[:min(top_n, len(current_mapping))]
         if use_annealing:
               random.shuffle(numbers)
         for i in range(len(numbers)):
               for j in range(i + 1, len(numbers)):
                  test_mapping = current_mapping.copy()
                  test_mapping[numbers[i]], test_mapping[numbers[j]] = \
                     test_mapping[numbers[j]], test_mapping[numbers[i]]
                  test_score = score_func(decrypt_with_mapping(encrypted_numbers, test_mapping))
                  accept = False
                  if use_annealing:
                     if test_score > current_score:
                           accept = True
                     else:
                           delta = test_score - current_score
                           probability = math.exp(delta / temperature)
                           if random.random() < probability:
                              accept = True
                              print(f"   Iteration {iteration}: Accepted worse solution (score {test_score}) "
                                    f"at temperature {temperature:.1f}")
                  else:
                     if test_score > current_score:
                           accept = True
                  if accept:
                     current_score = test_score
                     current_mapping = test_mapping
                     improved = True
                     if test_score > best_score:
                           best_score = test_score
                           best_mapping = test_mapping.copy()
                           print(f"   Iteration {iteration}: Score improved to {best_score} "
                                 f"(swapped {test_mapping[numbers[j]]}↔{test_mapping[numbers[i]]})")
                           attempts.append({
                              'iteration': iteration,
                              'score': best_score,
                              'mapping': best_mapping.copy(),
                              'preview': decrypt_with_mapping(encrypted_numbers, best_mapping)[:100],
                              'type': ngram_type
                           })
                     break
               if improved:
                  break
         if use_annealing:
               temperature *= cooling_rate
      print(f"   Optimization completed: {len(attempts)-1} improvements made")
      return best_mapping, best_score, attempts

   def frequency_attack(encrypted_numbers, language='english', optimize=True):

      1. Initial mapping based on letter frequencies

### Why RSA Is Harder to Break Than Caesar (Even Letter-by-Letter)

While both are vulnerable to frequency analysis, RSA letter-by-letter presents additional challenges:

1. **No obvious shift pattern**: In Caesar, once you find one letter, you know all letters. In RSA, each letter must be identified independently.

2. **Optimization required**: Caesar cipher can be broken by trying all 26 shifts. RSA requires sophisticated optimization algorithms (hill-climbing, n-gram analysis).

3. **Local maxima problem**: Simple hill-climbing can get stuck in suboptimal solutions, requiring advanced strategies like:
   - Simulated annealing
   - Multi-phase optimization
   - Focused search on rare letters

4. **Larger sample needed**: Accurate RSA frequency attack requires more text (~1000+ characters) compared to Caesar (~200 characters).

5. **Statistical noise**: With 26! possible letter mappings, finding the correct one requires careful scoring metrics and iterative refinement.

## Cryptographic Lessons

### Why Proper RSA Implementation Matters

**Secure RSA requires:**

1. **Block encryption**: Encrypt multiple characters together, not individually
   ```
   Wrong: Encrypt('H'), Encrypt('E'), Encrypt('L'), Encrypt('L'), Encrypt('O')
   Right: Encrypt('HELLO')
   ```

2. **Padding schemes**: OAEP (Optimal Asymmetric Encryption Padding)
   - Adds randomness to each encryption
   - Same plaintext produces different ciphertext
   - Prevents statistical attacks

3. **Large key sizes**: Minimum 2048-bit keys (617 decimal digits)
   - Makes factorization computationally infeasible
   - Our 10-bit example (n=3233) is factorable in microseconds

4. **Proper message format**: Never encrypt raw, predictable data
   - Hash messages before encryption
   - Use hybrid encryption (RSA + AES)

### Modern Cryptographic Standards

**What modern systems do right:**
- **TLS/SSL**: Uses RSA only for key exchange, not data encryption
- **PGP/GPG**: Applies OAEP padding to RSA-encrypted messages
- **Signal/WhatsApp**: Uses perfect forward secrecy, not pure RSA
- **Bitcoin**: Uses ECDSA (elliptic curves), not RSA

### Historical Context

**Frequency analysis origins:**
- Invented by Al-Kindi (9th century Arab mathematician)
- First documented cryptanalysis technique
- Broke all monoalphabetic substitution ciphers
- Remained the primary attack method for 1000+ years

**Modern relevance:**
- Shows why implementation details matter
- Demonstrates that mathematical strength ≠ practical security
- Illustrates the importance of proper cryptographic engineering
